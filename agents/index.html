Process

  1. 1. Visitor types. The line goes on the board in their own chalk.
  2. 2. Python gates. assets/triage.py owns the rules. Confident local answers never spend a token.
  3. 3. One handoff. A miss names one agent — never five at once — so ownership stays clear.
  4. 4. Reply path. The live flow on the homepage lights Typing → Python → agent → Response as it happens.
  5. 5. Check. Overclaim scan on the reply: nothing may claim to have read a live customer system.

Architecture

Static site on GitHub Pages. Homepage chat reaches an Apps Script reception endpoint for model turns. Local triage ships as compiled JS from the Python gatekeeper. The pipeline desk at /org/ is a dated snapshot of a development workspace of our own — not a live customer org.

Credentials and provider prompts for reception live outside this repository (Apps Script). Homepage framing can steer the client question; the remote system prompt is still the main source of reply tone.
