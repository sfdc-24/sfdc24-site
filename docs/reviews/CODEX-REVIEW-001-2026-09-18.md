## P0 — Blockers

### B1. Triage miss-route hardcodes Grok (correctness / honesty)

**Where:** `assets/triage.py` emitted `route()` (also present in committed `assets/triage.js`).

**What:** Scoring loop selects `best` / `bestScore` (keyword weights, else round-robin), then **ignores `best`**:

```javascript
return { id: "route", answer: "", handTo: "", routeTo: "grok", why: "escalate-to-grok", by: "python" };
```

**Why it matters:** Comments and CREW/ROUTING tables promise one reachable agent by keyword. Visitors (and board demos) are told Python routes fairly; the runtime always escalates to Grok. That is the same class of failure the file’s own history warns about: confident UI that does not match mechanism.

**Fix (minimal):**

```javascript
return { id: "route", answer: "", handTo: "", routeTo: best, why: why, by: "python" };
```

Then `python assets/triage.py`, commit **both** `triage.py` and `triage.js`, add a unit/assert that a Salesforce-shaped miss does not always yield `grok` when another CREW member scores higher.

**Acceptance:** Miss with Apex/LWC keywords → `routeTo: "claude"` (or current CREW name for that weight); no-signal misses rotate; regenerated JS matches py.

## P1 — Should-fix before relying on these tools overnight

### S1. Doctrine vs SEO artifacts

**Doctrine** (`docs/site-doctrine.md`): SEO out of scope — no sitemap, no crawler optimization.  
**Shipped:** `robots.txt` `Allow: /` + `Sitemap: https://www.sfdc24.com/sitemap.xml`; `sitemap.xml` lists public routes (and PR #72 even extends sitemap).

**Recommendation:** Either (a) delete/neutralize sitemap + stop linking it from robots (doctrine-true), or (b) amend doctrine if sitemap is an explicit Mr. Salam exception. Do not leave both.

### S2. `tools/site_edit_router.py` find_replace is multi-hit unsafe

`apply_find_replace` counts matches then `str.replace` **all** occurrences. A short needle can corrupt chrome/CSS/JS far from the intended homepage string.

**Poka-yoke:** refuse unless `count == 1` (or require explicit `"replace_all": true` in the request JSON). Surface count in the JSON result always.

### S3. Router git helpers ignore exit codes

`git([...])` / `maybe_commit` run `subprocess` without `check=True` or `returncode` tests. Failed `checkout`/`commit` still reports `ok: true` after a patch write.

**Poka-yoke:** fail closed on nonzero git status; never `git add -A` (stage only touched paths).

### S4. Triage answer swap regex is brittle

`apply_triage_answer` uses a wide `[\s\S]{0,400}` window between `"id"` and `"answer"`. Nested quotes / multi-line answers / dict reorders can miss or swap the wrong field.

**Poka-yoke:** parse RULES via `ast` or import `check()` + structured rewrite; always regenerate `triage.js` in the same successful transaction.

### S5. Manifest scope drift risk

`data/site-manifest.json` lists chrome assets and homepage inventory correctly enough for tier-zero, but:

- Live tree has many more public dirs (`governor/`, `intake/`, `voice/`, `xray/`, `looks/`, `projects/`, `review/`, `p/`, …) than `off_scope_examples`.
- Router correctly refuses off-manifest targets — good — yet operators may think “manifest = full site map.” Rename docs to **homepage edit allowlist**, not site map.

### S6. Bus / server script poka-yoke gaps (Blackboard staging helpers)

Observed against `/workspace/akatia-blackboard-staging/scripts` + uploads env (site review dependency):

| Gap | Risk |
| --- | --- |
| Long / hung `read` with weak progress | Overnight agents wait forever; CODEX-REVIEW board read-back timed out here |
| Title string must match Apps Script exactly (`Blackboard - Alpha DB`) | Silent empty/wrong board if hyphenation drifts |
| `bus_cli.append` hardcodes writer tag `grok` | Mis-attribution when other agents use the helper |
| Env discovery: `BLACKBOARD_ENV` vs repo `.env` vs `/workspace/uploads/blackboard.env` | Wrong machine → wrong bus; D-18 local-only is right, but fail with **which path was tried** |
| Semicolon vs comma recipient splitting (known fleet defect) | Dispatches to `codex;chatgpt-codex-desktop` can be invisible to some readers |

**Poka-yoke:** hard timeout + partial progress logs; print resolved env path (not secrets); append `from=` from argv; shared recipient tokenizer tests.

## P2 — Nits / solidify later

### N1. CREW naming vs fleet tags

`CREW_DEFAULT` uses product names (`claude`, `codex`, `grok`, …). Board / DOL tags use `claude-code-cli`, `chatgpt-codex-desktop`, `grok-bot`. Document the mapping next to ROUTING so “routeTo” is not confused with Blackboard `to=`.

### N2. Runtime clock rules are the right pattern

Empty `answer` + `runtime` answerers for Toronto date/time avoid build-time staleness — keep this; extend the same pattern to any other “facts that rot.”

### N3. Publisher is the quality bar for fail-closed tooling

`tools/prototype_publisher.py` (with tests/workflow) shows the desired shape: canonical work-id, digest pin, symlink refusal, robots `noindex` injection/validation, journaled removal. Router/triage should borrow that strictness, not the other way around.

### N4. First-person / org-noun guards are duplicated

Guards exist in triage `check()`, router `would_trip_guards`, and manifest inventory scan — good defense in depth; extract one shared module to prevent regex drift (`orgs?` vs `org`, etc.).

### N5. Agent reply contract is doctrine-binding

Doctrine § Agent reply contract (YES/NO first, ETA on YES) is the right overnight control plane. Metrics JSONL + this review honor it; wire the same contract into triage *escalation* replies if models speak on-page.
